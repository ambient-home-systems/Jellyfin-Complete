Review queue: design notes

Built for a weekly batch: filter, select a group, approve. One row per proposal. Example titles are real list entries; whether you own them is illustrative.

  1. 1

    Dry-run banner

    This is the one screen where dry run changes the meaning of a button, so it says so plainly in a yellow banner at the top. Approving still applies the change right away; dry run only stops Auto.

  2. 2

    Add cap, as a running total

    The Radarr and Sonarr guardrail reads "1 / 10" with a bar, like a tape side that must not overflow. When it fills, further adds stay queued here rather than failing, and the bar turns red, because a full cap is something to look at.

  3. 3

    Groups, bulk and safe dismissal

    Proposals are grouped by collection, then by action type, each with a group checkbox. The bulk bar sticks to the top of the list.

    Approve is the primary action. Selected rows turn yellow, the timetable's selection colour; red is kept for failures. Snooze takes a duration, including "until the window opens". Dismiss sits apart, and both snoozes and dismissals can be undone from their tabs.

    Each row explains itself: the source and rank, how it was matched, and for removals why it left, with "source healthy" because a failed source never proposes a removal. Radarr rows list the guardrail checks they passed.
